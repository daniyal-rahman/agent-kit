# UI/UX design

- **References.** Real screens of the best comparable products at the same state.
  Look past the first result (Page Flows, Mobbin, open-source apps): many common
  apps aren't the bar. Note what to borrow and why, keeping flows apart from look.
  Use an existing library or pattern before inventing one.
- **Style reference.** Extend the existing identity. If there isn't one, make a
  style reference first: one underlying idea carried through imagery, palette,
  type, icons and a realistic product fragment. Show the owner a few directions
  that each change the whole idea, and refine the one picked. When a reaction is
  vague ("ugly"), work out the cause yourself. Save the chosen reference in the
  repo; it anchors every later screen.
- **Storyboard** the key screens and flow for the owner before building them out.
- **Simplicity.** A strong reference chooses what to show, hide and play down;
  work out why each element earns attention at that moment. Remove or regroup
  before adding a label, subtitle or outline. Lead with the useful action.
- **Defaults.** One considered default; advanced choices out of the way.
- **Real use.** Realistic content and every state (empty, working, error, done).
  Match the platform's conventions. Keep motion from shifting layout.
- **Library.** One shared component and asset library, reused across the app.
- **Proof.** Walk the actual task in the running app, at each size and state the
  change touches, and send the owner the screenshots in the chat. The reviewer
  judges what is on screen, not the diff.
- **Climb** with `hill-climb`: the judge compares yours with the references side
  by side. Rubric: task flow, hierarchy, consistency, typography, colour and
  contrast (light and dark), icons and polish.
